# Lambda Artifact Store

This directory defines the shared Amazon S3 bucket intended to hold packaged
Python Lambda deployment artifacts. It is training-range infrastructure under
`infra/`, not infrastructure owned by an individual lab.

The CloudFormation template is repository source describing intended state. It
does not establish that the bucket or its stack is deployed, and it does not
authorize an AWS operation.

## Template behavior

[`template.yaml`](template.yaml) creates one general-purpose S3 bucket with:

- all four S3 Block Public Access settings enabled
- ACLs disabled through `BucketOwnerEnforced` object ownership
- default server-side encryption using S3-managed keys (`AES256`)
- versioning enabled
- standard `Project`, `Environment`, and `ManagedBy` tags
- no explicit bucket name, allowing CloudFormation to generate a valid unique
  physical name

The template intentionally does not create a KMS key, bucket policy, IAM role,
access point, replication configuration, logging destination, deployment
automation, or automatic bucket-emptying resource. Permissions for systems
that publish or consume artifacts belong in their separately governed
infrastructure.

## Parameters and output

| Parameter | Default | Operator-configuration relationship |
| --- | --- | --- |
| `ProjectTagValue` | `aws-training` | `resources.tags.Project` |
| `EnvironmentTagValue` | `training` | `resources.tags.Environment` |
| `ManagedByTagValue` | `aws-training` | `resources.tags.ManagedBy` |

The defaults match [`.aws-training.example.toml`](../../.aws-training.example.toml).
For an account-specific deployment, the corresponding values come from the
gitignored `.aws-training.local.toml`. The template does not read either TOML
file, load credentials, select a profile or Region, or create a second
operator-configuration system. Passing those values and performing required
AWS safety checks remain responsibilities of a separately authorized future
deployment workflow.

The `ArtifactBucketName` output contains the physical bucket name generated by
CloudFormation. Consumers should obtain the bucket name from that output
rather than reconstructing or assuming it.

## Lifecycle behavior

The lifecycle rule uses the current `NoncurrentVersionExpiration` and
`NoncurrentDays` CloudFormation properties:

- A current object version has no expiration policy and remains until it is
  superseded or deliberately deleted.
- A noncurrent object version becomes eligible for permanent deletion after
  14 days.
- An incomplete multipart upload is aborted after 1 day.

An artifact uploaded under a unique key remains the current version of that
key indefinitely. The noncurrent-version rule bounds storage for superseded
versions; it does not provide age-based cleanup for every historical artifact.
Artifact-key and current-version cleanup policy therefore remains a concern for
the future publishing workflow.

## Persistence and cleanup

The bucket uses `DeletionPolicy: RetainExceptOnCreate`. If the stack operation
that first creates the bucket rolls back, CloudFormation attempts to delete the
new bucket instead of retaining an unused resource. After successful creation,
removing the resource from the template or deleting the stack retains the
bucket and its objects.

Retention does not leave the bucket managed by a deleted stack. CloudFormation
removes the resource from its management while the physical bucket continues
as a separately managed resource. It continues to incur applicable storage and
request charges until deliberately adopted or deleted.

The bucket also uses `UpdateReplacePolicy: Retain`. If a template update ever
replaces the physical bucket, CloudFormation retains the old bucket while the
stack output changes to identify the replacement. The old bucket is then
outside CloudFormation management and requires deliberate inventory, data
handling, and cleanup. Neither stack deletion nor replacement automatically
empties a retained bucket.

## Local validation

Run the pinned CloudFormation linter without contacting an AWS account:

```sh
uv run --project tools/cloudformation --locked --isolated \
  cfn-lint infra/artifact-store/template.yaml
```

The isolated uv project resolves the committed dependency lock outside the Git
working tree. A successful lint establishes only that the repository template
passes the configured local checks; it is not evidence of deployment or
current AWS state.
